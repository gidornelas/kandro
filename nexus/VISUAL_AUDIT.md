# Visual Audit — NEXUS Frontend

> Generated by @vision (ux-engineer phase)
> Date: 2026-05-04

## Visual Issues

1. **Inline styles pervasive** — Almost all components use inline `style={{...}}` instead of Tailwind classes or CSS modules. This makes visual consistency harder to maintain and defeats the purpose of having Tailwind configured.

2. **No design token system** — Colors, spacing, and typography use raw CSS variables (`--acc`, `--s1`, `--t3`) without a centralized token definition. Values are scattered across components.

3. **Inconsistent spacing** — Sidebar items use `height: 30`, `padding: '0 8px'`; voice tiles use `padding: 12`; chat messages use `padding: '6px 10px'`. No consistent 4px/8px grid.

4. **Tooltip implementation** — Uses native `title` attribute (per IMPLEMENTATION_SUMMARY.json) instead of Radix Tooltip. Lacks styling consistency.

5. **SettingsModal inline styles** — Uses inline styles for spacing instead of design tokens (noted in previous audit).

6. **PermissionToggle touch target** — Button padding `4px 10px` results in ~28px height, below the 44px WCAG minimum.

7. **TeamBadge size** — 8px size may be too small for clear visual distinction on Kanban cards.

8. **VoiceRoom heavy inline styles** — 353 lines of component with deeply nested inline styles. Hard to maintain.

9. **No loading/skeleton states** — Components render immediately with data; no loading indicators when fetching from API.

10. **No empty states** — Lists (channels, DMs, files) have no empty state illustrations or messages.

## Accessibility Findings

1. **Skip link present** ✅ — App.tsx has "Pular para conteúdo principal" link with proper focus behavior.

2. **Focus states** — Interactive elements use CSS variables for focus, but visibility depends on browser defaults. No custom focus ring implementation.

3. **Color-only information** — Status dots (online/busy/away) use color only in some places. Text labels accompany in Sidebar but not consistently.

4. **Touch targets undersized** — PermissionToggle (28px), VoiceRoom header buttons (34px), sidebar items (30px) are below 44px minimum.

5. **Heading hierarchy** — No explicit heading levels (`<h1>`, `<h2>`) in components. Uses `<span>` with font-weight for visual hierarchy only.

6. **ARIA labels** — Minimal ARIA usage. `role="application"` on root div. Most interactive elements lack `aria-label`.

7. **Keyboard navigation** — No visible focus styles on custom buttons. Voice layout switcher, sidebar items, and kanban cards may not be keyboard accessible.

8. **Modal focus management** — SettingsModal and PermissionModal handle escape key but focus trapping is unclear.

9. **Screen reader labels** — Status indicators in sidebar have some labels but voice participants, kanban cards, and file items lack them.

10. **Reduced motion** — No `prefers-reduced-motion` media query handling for animations (livepulse, wavebar).

## Recommended Changes

### High Priority (Fase 1-2)
1. Create `src/styles/tokens.css` with centralized design tokens
2. Convert inline styles to Tailwind classes or CSS modules
3. Add `aria-label` to all interactive elements
4. Increase touch targets to minimum 44px
5. Add focus-visible styles globally

### Medium Priority (Fase 3-4)
6. Add loading skeleton components for all data-fetching views
7. Add empty state illustrations for lists
8. Implement heading hierarchy with proper HTML elements
9. Add `prefers-reduced-motion` support
10. Implement focus trapping in all modals

### Low Priority (Fase 7-8)
11. Run axe-core audit and fix critical issues
12. Add keyboard navigation for kanban drag-and-drop
13. Implement high contrast mode
14. Add alt text for all decorative images/icons

- [ ] axe-core audit passes with 0 critical violations

- [ ] Empty states present for all lists

- [ ] Heading hierarchy logical and semantic
